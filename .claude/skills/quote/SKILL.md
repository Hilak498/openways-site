# סוכן הצעות המחיר של Open Ways

הסוכן הזה מוציא הצעות מחיר בשם בעל העסק ושולח אותן ללקוחות אמיתיים. זו פעולה
שיוצאת החוצה ולא ניתן לבטל אותה: מייל שיצא, יצא. לכן כל התהליך בנוי סביב כלל
אחד - **בעל העסק מאשר במפורש כל הצעה לפני שהיא נשלחת, ורק אחריו שולחים.**

## הקבצים

| קובץ | תפקיד |
| --- | --- |
| `services.json` | קטלוג השירותים והמחירים. **לא בגיט** (הריפו ציבורי). |
| `services.example.json` | התבנית לקטלוג, עם מחירים ריקים. כן בגיט. |
| `scripts/build_quote.py` | בונה HTML + PDF מעוצבים מתוך הקטלוג ופרטי הלקוח. |
| `scripts/track.py` | מוסיף ומעדכן שורות ב-`tracking.csv`. |
| `out/<מספר הצעה>/` | ההצעות שנוצרו. לא בגיט. |
| `tracking.csv` | מעקב אחר כל ההצעות. לא בגיט - יש בו פרטי לקוחות. |

הריפו הזה ציבורי. שמות לקוחות, מיילים, טלפונים ומחירים לא נכנסים לגיט לעולם -
לא בקומיט, לא בהודעת קומיט ולא בקובץ חדש. אם צריך לגבות את המעקב, מעלים את
`tracking.csv` ל-Google Drive.

## לפני שמתחילים

בדוק ש-`services.json` קיים. אם לא - העתק אותו מ-`services.example.json`, ואמור
למשתמש אילו שדות חסרים כדי שימלא אותם. אל תמציא מחירים, אל תשתמש במחירי שוק
משוערים ואל תשלים פרטי עסק חסרים מתוך האתר: הצעת מחיר עם מספר שהומצא היא נזק
עסקי אמיתי. `build_quote.py` יעצור מעצמו על שדה ריק, וזו התנהגות רצויה.

## התהליך

### 1. איזה שירות

הצג את האפשרויות מתוך `services.json` כרשימה ממוספרת לפי משפחות שירות, עם
המחיר שמוגדר לכל אחת. אם המשתמש כבר אמר איזה שירות - אל תשאל שוב, רק ודא את
הרמה. לשלוש רמות המשכנתא יש שדה `criteria` שמגדיר מה מכניס תיק לכל רמה: עבור
עליהן עם המשתמש כשהוא מתלבט בין בסיסי למורכב, במקום לנחש. הפער בין הרמות הוא
פער במחיר ובעבודה, וטעות לכאן או לכאן פוגעת במישהו.

### 2. פרטי הלקוח והתיק

אסוף בשאלה אחת מרוכזת, לא בטפטוף:

- שם הלקוח, ואם זו חברה - שם החברה ואיש הקשר
- מייל לשליחה, וטלפון
- ח.פ / ע.מ, אם יש
- משפט אחד שמסביר למה התיק נכנס לרמה הזו (`scopeNote` - מופיע בהצעה עצמה,
  והוא מה שגורם ללקוח להרגיש שההצעה נכתבה בשבילו)
- שינויים מהתנאים הרגילים: הנחה, סעיף שנוסף או ירד, תוקף חריג

### 3. בניית ההצעה

כתוב `payload.json` והרץ:

```bash
python3 .claude/skills/quote/scripts/build_quote.py /tmp/payload.json > /tmp/build.json
cat /tmp/build.json
```

הסקריפט מחזיר שורת JSON עם מספר ההצעה, הסכום ונתיבי ה-HTML וה-PDF. הוא גם
מספר את ההצעות ברצף לפי שנה (OW-2026-001), כך שאין שתי הצעות עם אותו מספר.

מבנה ה-payload:

```json
{
  "service": "mortgage-complex",
  "client": {"name": "דנה כהן", "company": "", "email": "dana@example.com",
             "phone": "052-0000000", "taxId": ""},
  "scopeNote": "התיק כולל הכנסות מעסק עצמאי ומכירת דירה קיימת במקביל לרכישה.",
  "overrides": {"discount": {"label": "הנחת לקוח חוזר", "amount": 500}}
}
```

### 4. אישור - התחנה שאי אפשר לדלג עליה

שלח למשתמש את קובץ ה-PDF (`SendUserFile`) ולצידו סיכום קצר: הלקוח, השירות,
הסכום הסופי כולל מע"מ, **כתובת המייל המדויקת שאליה זה הולך**, ותוקף ההצעה.
ואז שאל במפורש אם לשלוח.

חכה לתשובה מפורשת. "כן", "שלח", "אישור" - זה אישור. שתיקה, "נראה טוב", "אוקיי
מעניין" או תיקון של פרט אחד - אלה לא אישורים לשליחה. אם המשתמש ביקש תיקון,
תקן, בנה מחדש והצג שוב לאישור. אישור להצעה אחת אינו אישור להצעה הבאה.

אם כתובת המייל לא הגיעה מהמשתמש בשיחה הזו - אל תשלח לפני שהוא אישר אותה
בפירוש. כתובת שגויה שולחת את המחירים שלך לאדם הלא נכון.

### 5. שליחה

שלח עם `mcp__Gmail__send_message`: ה-PDF כקובץ מצורף (base64), נושא ענייני
וגוף מייל קצר בעברית. הגוף לא חוזר על ההצעה - הוא רק פותח אותה:

> שלום {שם},
>
> מצורפת הצעת מחיר ל{שירות}, בהתאם לשיחתנו.
> ההצעה בתוקף עד {תאריך}. אשמח לענות על כל שאלה.
>
> בברכה,
> {שם החותם}, Open Ways
> {טלפון} · {מייל}

לצירוף הקובץ:

```bash
base64 -w0 .claude/skills/quote/out/OW-2026-001/quote.pdf
```

ואז `attachments: [{filename: "הצעת מחיר - Open Ways.pdf", mimeType: "application/pdf",
content: "<base64>"}]`. אחרי השליחה מסור למשתמש שנשלח, למי, ומתי מומלץ לעקוב.

### 6. מעקב

מיד אחרי שליחה מוצלחת:

```bash
python3 .claude/skills/quote/scripts/track.py add --from-build /tmp/build.json \
  --status נשלחה --contact "דנה כהן" --phone "052-0000000"
```

זה קובע גם תאריך מעקב (ברירת מחדל: 4 ימים). אם ההצעה נבנתה ולא נשלחה, רשום
אותה עם `--status טיוטה` - הצעה שהוכנה ולא יצאה היא בדיוק מה שנוטים לשכוח.

עדכון סטטוס בהמשך:

```bash
python3 .claude/skills/quote/scripts/track.py update OW-2026-001 --status אושרה --note "חתמו"
python3 .claude/skills/quote/scripts/track.py list --open
python3 .claude/skills/quote/scripts/track.py due
```

`due` מחזיר את ההצעות שהגיע מועד המעקב שלהן. הסקריפט גם מסמן אוטומטית הצעות
שפג תוקפן, כדי שהרשימה לא תציג כפתוחה הצעה שכבר מתה.

## עבודה מהיומן

כשכלי Google Calendar זמינים בשיחה, אפשר לעבוד יזום: קרא את הפגישות של היום
ושל מחר, הצלב מול `track.py list --open` ומול `due`, והצע למשתמש רשימה קצרה -
"אחרי הפגישה עם X מתבקשת הצעה ל{שירות}; להצעה של Y יש מעקב היום". הצע, אל
תבצע: גם כאן ההצעה נבנית ונשלחת רק אחרי אישור מפורש.

אם הכלים לא זמינים, אמור זאת במקום לנחש מהיומן - המחבר של Google Calendar מותקן
בחשבון אבל צריך להפעיל אותו עבור השיחה הזו בהגדרות המחברים.

## גיבוי ל-Drive

`tracking.csv` נמצא רק במחשב הזה, וסביבת עבודה מרוחקת נמחקת בסוף הסשן. אחרי
עדכון מעקב, אם כלי Google Drive זמינים: חפש `openways-quotes-tracking.csv`,
ואם קיים - עדכן אותו בתוכן החדש; אם לא - צור אותו. כדאי להעלות לשם גם את
קובצי ה-PDF של הצעות שנשלחו.

## טעויות שכדאי להימנע מהן

- **להמציא מחיר** כשהשדה ריק ב-`services.json`. עצור ובקש את המספר.
- **לשלוח בלי אישור**, או לפרש "נראה טוב" כאישור.
- **לקמט את ההצעה לגוף המייל** במקום לצרף את ה-PDF. המסמך המעוצב הוא המוצר.
- **לרשום פרטי לקוח בגיט**, כולל בהודעות קומיט ובקבצי בדיקה.
- **לשכוח את המעקב.** הצעה שנשלחה ולא נרשמה היא הצעה שאבדה.
